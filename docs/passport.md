# Паспорт проекта

> Шаблон для заполнения на паре 5. Примеры в скобках — из эталона ShoeShop.
> Файл живёт в репозитории: `docs/passport.md`

## 1. Название проекта

Магазин обуви "Твой выбор"

## 2. Проблема

У небольшого магазина обуви каталог — на бумаге и в Excel: клиент не может посмотреть товар и оформить заказ, продавец путается в остатках». 

## 3. Пользователи

клиент магазина — выбирает товар и оформляет заказ; продавец-консультант — ведёт каталог и остатки; администратор — управляет пользователями и правами». 

## 4. Цель проекта

Создать систему, которая позволит клиенту выбрать обувь и оформить заказ, а сотрудникам - управлять каталогом и актуальными остатками

## 5. Метрики успеха


- время оформления заказа — < 2 минут;
- клиент находит товар через поиск/фильтры — за < 3 кликов;
- остатки обновляются сразу после продажи, без ручного ввода. 

## 6. Границы (что НЕ делаем)

не подключаем реальные платёжные шлюзы (оплата — учебный симулятор); нет мобильного приложения; доставка курьером не моделируется — заказ выдаётся в магазине

## 7. Риски

не успеем метрики к дедлайну → сначало важное все другое потом; сложно придумать 30+ товаров → берём реальный ассортимент из открытых источников. Ошибки в БД: регулярно тестируем работу MySQL. Нехватка времени : распределяем задачи
